Odlox Language Reference

Introduction

Odlox is a bytecode interpreter for the Lox language, from Bob Nystrom's Crafting Interpreters, written in Odin and extended with Python-inspired features and Raylib graphics bindings. Its design follows the bytecode-VM approach the book builds in C (clox) — a single-pass compiler emitting bytecode for a stack-based virtual machine with its own mark-and-sweep garbage collector.

On top of vanilla Lox, Odlox adds: lists, tuples, dictionaries and slicing; exceptions with try/except; module imports; foreach/range iteration; integer arithmetic and modulus; break/continue; const; implicit variable declaration; string interning; native vector types (vec2/vec3/vec4); a float_array type; a native 3D physics_world simulation; a box2d module wrapping Odin's Box2D v3 bindings for 2D rigid-body physics; and Raylib bindings for 2D graphics.

This document is the complete language and library reference.

No semicolons requiredOdlox does not require semicolon line terminators. A newline ends a statement, so ; is optional (both styles are accepted). Most examples in this reference omit them. See Variables.
Reading the signaturesMethod and function signatures are shown in monospace boxes. Arguments in italics describe the expected value type. Unless noted, vec4 colours use 0–255 RGBA components.

Running Odlox

Build the interpreter and run a script:

// Build (debug: -vet/-strict-style lints, and the --debug/--instrument trace hooks compiled in)
bin/build.sh
// Build (release: -o:speed -disable-assert -no-bounds-check, no trace hooks)
bin/build.sh --release

// Run a script
bin/odlox.exe script.lox

// Start the REPL
bin/odlox.exe --repl

// Set LOX_PATH so module imports resolve
. ./setenv.ps1     // PowerShell
. ./setenv         // bash

Bytecode cacheImported modules (never the entry script) are cached as compiled bytecode in a __loxcache__/<name>.lxc file alongside the module's own source — the cache is used whenever it exists and is newer than the source, and is invalidated (recompiled and refreshed) the moment the source changes. --force-compile skips the cache lookup for that run but still refreshes it afterward.

If neither a usable cache nor a source file can be found, the import still fails cleanly with the ordinary "Module not found" error.

The REPL

bin/odlox.exe --repl starts an interactive session. State persists across lines: variables, functions, and classes defined on one line remain in scope for every later line.

> var x = 10
> fun add(a) { return a + x }
> print add(5)
15

Definitions can span multiple lines. When a line leaves brackets open ({ }, ( ), [ ]) or a string unterminated, the prompt changes to ... and input is buffered until the statement is complete:

> fun greet(name) {
...   return "hello, ${name}"
... }
> print greet("world")
hello, world

Pressing Enter on an empty line exits the REPL; pressing it while a multi-line entry is still open (at the ... prompt) cancels that pending entry and returns to the > prompt.

Runtime errors don't end the sessionAn error on one line is reported and the REPL continues — previously defined variables and functions are still available on the next line.

Comments

Line comments start with // and run to the end of the line. There are no block comments.

// This is a comment
a = 1   // trailing comment

Variables & const

Odlox supports both explicit (var) and implicit variable declaration. Assigning to a new name creates it; no var is required.

var a = 1     // explicit declaration
b = 2         // implicit — assignment creates the variable
a = a + b     // reassignment

const

const declares a variable that cannot be reassigned. Attempting to reassign a const is a compile-time error.

const PI = 3.14159
const MAX_ENTITIES = 500

Destructuring assignment

Lists and tuples can be unpacked into multiple variables in one statement.

a, b, c = [1, 2, 3]
x, y, z = (10, 20, 30)

Statement terminators

Statements may be terminated with a semicolon ; or simply a newline — both are accepted, so semicolons are optional.

A closing brace } also terminates the statement immediately before it, so braced blocks may be written on a single line: if (x) { print 1 } and if (x) { a() } else { b() } are valid.

Use ; to split statements on one lineBecause a newline is the usual statement terminator, two statements sharing a single line must be separated with a semicolon ; — otherwise the parser cannot tell where one ends and the next begins. This applies inside single-line blocks: while (i < 3) { print i; i = i + 1 } and { const c = 7; print c }. The semicolon is only needed between statements; the last one before } needs none, since the brace terminates it.

Compound assignment

The compound-assignment operators +=, -=, *=, /=, and %= work on variables and object properties. As with the binary operators, / on two integers is integer division and % requires integer operands. Vector properties may also use ++ forms via the property compound path.

a = 5
a += 1        // 6
a -= 2        // 4
a *= 3        // 12
a /= 4        // 3   (integer division)
a %= 2        // 1

p = vec2(1, 2)
p.x += 1      // 2
p.y *= 3      // 6

Conditional expression (ternary)

The C-style ternary operator cond ? a : b evaluates cond and yields a if it is truthy, otherwise b. Only the selected branch is evaluated. It is an expression, so it can appear anywhere a value is expected. It is right-associative, so c1 ? a : c2 ? b : c groups as c1 ? a : (c2 ? b : c).

n = 1
var label = n == 1 ? "item" : "items"   // "item"

// only the chosen branch runs
x = ok ? compute() : fallback()          // fallback() not called when ok is truthy

// right-associative chaining
grade = s >= 90 ? "A" : s >= 80 ? "B" : "C"

Control flow

if / else

if (x > 10) {
    print "big"
} else if (x > 0) {
    print "small"
} else {
    print "non-positive"
}

while

i = 0
while (i < 5) {
    print i
    i = i + 1
}

for

for (var i = 0; i < 10; i = i + 1) {
    if (i == 5) break
    if (i % 2 == 0) continue
    print i
}

foreach

foreach iterates any iterable: lists, tuples, strings, range(), or a class implementing the iterator protocol (see Classes).

foreach (item in [1, 2, 3]) {
    print item
}

foreach (ch in "abc") {
    print ch
}

range

range() returns an efficient native integer iterator. Using foreach (i in range(n)) is significantly faster than an equivalent manual for loop.

foreach (i in range(5))        { print i }   // 0..4
foreach (i in range(2, 8))     { print i }   // 2..7
foreach (i in range(0, 10, 2)) { print i }   // 0,2,4,6,8
Performance tipPrefer foreach (i in range(n)) over a manual counter for loop — range() is a native iterator and avoids per-iteration bytecode overhead.

break / continue

break exits the innermost loop; continue skips to the next iteration. Both work in for, while, and foreach.

Functions

Functions are declared with func (or the alias fun). They are first-class values and support closures.

func add(a, b) {
    return a + b
}

func make_counter() {
    count = 0
    func inc() {
        count = count + 1     // closes over `count`
        return count
    }
    return inc
}

c = make_counter()
print c()   // 1
print c()   // 2

A function with no return returns nil. Functions can be passed as arguments and stored in variables, lists and dicts — see functools for map/filter/reduce.

Default parameters

A parameter may be given a default value with name=expr. The default is used when the caller omits that argument. Defaults are evaluated at call time, once per call — so a fresh value is produced each time (no shared mutable-default trap), the default may be any expression (including a function call), and it may reference earlier parameters.

func greet(name, greeting="hi") { return greeting & ", " & name }
print greet("Sam")            // hi, Sam
print greet("Sam", "yo")      // yo, Sam

func f(n, m=n*2) { return m } // default references an earlier parameter
print f(4)                    // 8

func acc(x, items=[]) { items.append(x); return items }
print acc(1)                  // [ 1 ]   (fresh list every call)
print acc(2)                  // [ 2 ]

All defaulted parameters must come after the non-default (required) ones — a required parameter may not follow a defaulted one.

Variadic parameters (*rest)

A trailing *name parameter collects any surplus positional arguments into a fresh list. It must be the last parameter, and combines with required and default parameters.

func sum(*xs) { var t = 0; foreach (x in xs) { t = t + x } return t }
print sum()                   // 0
print sum(1, 2, 3)            // 6

func lead(a, *rest) { return str(a) & "/" & str(len(rest)) }
print lead("x", 1, 2)         // x/2

func mix(a, b=10, *rest) { ... }   // required, then default, then *rest

Anonymous functions (lambdas)

Omit the name to write a function as an expression. Anonymous functions are ordinary closures — they capture surrounding variables (and this inside a method) just like named ones — and are handy as inline callbacks:

var add = func (a, b) { return a + b }
print add(2, 3)                       // 5

// inline callbacks for higher-order functions
print functools.map([1, 2, 3], func (x) { return x * x })     // [ 1 , 4 , 9 ]
print functools.filter(xs, func (x) { return x > 0 })

// immediately-invoked
print (func () { return 7 })()        // 7

The body is a normal braced block with an explicit return (there is no expression-body shorthand). Since an anonymous function has no name, it cannot refer to itself for recursion — assign it to a variable first and call through that.

func in statement position is a declarationA statement that begins with func is always parsed as a named declaration, so write lambdas where an expression is expected (after =, as a call argument, inside a list/dict, after return). To invoke one immediately, wrap it in parentheses: (func () { … })().

Classes

Classes support single inheritance, an __init__ constructor, instance methods, this, super, and static methods and class variables.

class Animal {
    __init__(name) {
        this.name = name
    }
    speak() {
        return this.name & " makes a sound"
    }
}

class Dog < Animal {          // Dog inherits from Animal
    __init__(name) {
        super.__init__(name)       // call parent constructor
    }
    speak() {
        return this.name & " barks"
    }
}

d = Dog("Rex")
print d.speak()   // "Rex barks"

Static methods

Methods declared static are called on the class itself rather than an instance.

class MathHelper {
    static square(x) {
        return x * x
    }
}
print MathHelper.square(5)   // 25

Class variables

A static field (no parentheses following the name) declares a class variable — a value that lives on the class itself rather than on any instance. It's declared with an optional initializer (defaulting to nil when omitted, like a bare var) and read or written from anywhere with ClassName.field, including from inside the class's own methods. There is no implicit this.field access to a class variable — use the class name explicitly.

Reading a class variable through a subclass walks up to the nearest ancestor that has it set, so a base class can track state shared across all its subclasses. Writing through a subclass always creates or updates that subclass's own value, shadowing the ancestor's without changing it.

class Animal {
    static count = 0

    __init__(name) {
        this.name = name
        Animal.count = Animal.count + 1
    }
}

class Dog < Animal { }

Animal("Rex")
Dog("Fido")
print Animal.count   // 2
print Dog.count      // 2, shared read via the superclass chain

Dog.count = 99        // shadows Animal.count, only for Dog
print Animal.count    // still 2

__str__ magic method

If a class defines __str__() returning a string, it is used whenever an instance is printed or passed to str().

class Point {
    __init__(x, y) { this.x = x; this.y = y }
    __str__() { return "Point(" & str(this.x) & ", " & str(this.y) & ")" }
}
print Point(3, 4)   // Point(3, 4)

Iterator protocol

A class becomes foreach-iterable by implementing __iter__ (returning an iterator object) and that iterator implementing __next__, which returns successive values and nil to signal the end.

class Range2 {
    __init__(n) { this.n = n }
    __iter__() { return Range2Iter(this.n) }
}
class Range2Iter {
    __init__(n) { this.n = n; this.i = 0 }
    __next__() {
        if (this.i >= this.n) return nil
        v = this.i
        this.i = this.i + 1
        return v
    }
}
foreach (x in Range2(3)) { print x }   // 0, 1, 2

Exceptions

Odlox provides try/except/finally exception handling. A built-in Exception base class is available; subclass it for custom exceptions. Handlers bind the caught instance with as.

class MyError < Exception {
    __init__(msg) {
        super.__init__(msg)
        this.name = "MyError"
    }
}

try {
    raise MyError("something failed")
} except MyError as e {
    print "caught: " & str(e)
} except Exception as e {
    print "other: " & e.name
}
  • Multiple except clauses handle different exception types; the first matching type wins.
  • try/except blocks may be nested.
  • raise instance throws an exception instance.
  • The runtime raises catchable exceptions such as RunTimeError and EOFError.

finally

An optional finally clause runs exactly once no matter how the try is left: normal completion, a caught exception, an exception that isn't caught here (it still propagates afterward), or a return/break/continue that jumps out of the try or an except body. except is optional as long as finally is present, so a bare try { ... } finally { ... } is valid.

func readFirstLine(path) {
    var f = os.open(path, "r")
    try {
        return os.readln(f)
    } finally {
        os.close(f)    // runs whether readln() returns normally or raises
    }
}
  • A new exception raised from inside finally itself supersedes whatever was already propagating -- the enclosing except (if any) catches the new one, matching Python's finally semantics.
  • Known limitation: if an except clause's own body raises a fresh exception, the enclosing finally does not run for it -- only exceptions escaping the try body itself (uncaught here) and normal/`return`/`break`/`continue` exits are covered.

Modules & imports

Modules are imported by name and compiled from source, or loaded from a bytecode cache if a fresh one exists (see Running Odlox) — the entry script itself always compiles from source.

import math
import particle_sys as ps        // alias
import random, colour as clr     // multiple, with alias

from … import

Selectively import names into the current namespace, or import everything with *. This works for both file modules and the native built-in modules.

from math import sin, cos, PI
from colour import *
from gfx import window, batch     // native built-in module

Resolving import foo to a file tries, in order: $LOX_PATH/modules/foo.lox (the standard library); foo.lox alongside the top-level script being run; then foo.lox in any subdirectory of that script's own directory, searched recursively — so a project's own modules can be grouped into subfolders without changing how they're imported. Built-in modules are registered natively and need only be imported, not resolved from disk: sys, os, inspect, colour_utils, gfx (window, batch, texture, shader, camera, …), physics (physics_world), box2d (box2d.world), and sound.

Numbers

Odlox distinguishes integers from floats. Integer literals have no decimal point; arithmetic between two integers stays integer (including /), while any float operand promotes the result to float.

a = 10
b = 3
print a / b     // 3   (integer division)
print a % b     // 1   (modulus)
print a / 3.0   // 3.3333333333333335  (float)
print int(3.9)  // 3
print float(3)  // 3.0

See the math module for trigonometry, roots, rounding and vector maths, and built-in functions for int(), float(), and rand().

Strings

Strings are immutable. Short strings (40 bytes or under — identifiers, small literals/values) are interned to one canonical object internally, so equality and dict/property/global lookups are a pointer compare, not a byte-by-byte one; longer strings are ordinary garbage-collected values with the same behavior otherwise. They support concatenation, repetition, slicing, membership and iteration.

s = "hello"
print len(s)          // 5
print s & " world"    // concatenation
print "@" * 3         // "@@@"  (repetition, either operand order)
print s[0]            // "h"
print s[1:3]          // "el"   (slice)
print "ell" in s      // true   (substring test)
foreach (c in s) { print c }   // iterate characters

String interpolation

Any ${ expression } inside a string literal is evaluated and spliced into the result. It works in both "…" and '…' literals, and the embedded expression may be arbitrary (arithmetic, calls, indexing, method calls, even nested strings). Each value is stringified via the same path as str() / print, so ints, floats, bools, nil, and class instances (through their __str__ method) all format correctly.

count = 3;
pct = 42.5;
print "total: ${count} (${pct}%)"   // total: 3 (42.5%)
print "next is ${count + 1}"         // next is 4
print "upper: ${"hi".replace("h", "H")}"  // upper: Hi

Write a literal $ as $$ (so $${x} yields a literal ${x}); a lone $ not followed by { is already literal. Interpolation is pure syntax sugar: "a${x}b" desugars to ("a" & str(x) & "b"), so it composes with everything strings already support.

String methods

s.replace(old, new) → string

Returns a copy of s with all occurrences of old replaced by new.

s.join(list) → string

Joins a list of strings using s as the separator. All list elements must be strings.

print "|".join(["a", "b", "c"])   // "a|b|c"

Related built-in functions

  • replace(s, old, new) — free-function form of .replace.
  • format(fmt, args...) — printf-style formatting (wraps Odin's core:fmt.aprintf).

Lists

Lists are mutable, ordered, and can hold values of any type.

a = []
b = [1, 2, 3]
b.append(4)          // [1, 2, 3, 4]
x = b[0]             // 1
b[1] = 42            // [1, 42, 3, 4]
c = a & b            // concatenation
if (3 in b) { print "found" }
p, q, r, s = b       // destructuring

Slicing & slice assignment

a = [0, 1, 2, 3, 4]
print a[1:3]     // [1, 2]
print a[:2]      // [0, 1]
print a[2:]      // [2, 3, 4]
print a[:]       // full copy
a[2:5] = [7, 8, 9]   // slice assignment

List methods

list.append(value) → nil

Adds value to the end of the list, in place.

list.remove(index) → nil

Removes the element at the integer index, in place. (Note: removal is by index, not by value.)

list.find(value) → int | nil

Returns the index of the first element equal to value, or nil if not present.

list.length() → int

Returns the number of elements. Equivalent to len(list).

list.clear() → nil

Empties the list in place, keeping its existing capacity — for a list that gets emptied and refilled every frame/iteration, cheaper than reassigning list = [], which allocates a brand new list.

Also availableThe built-in append(list, value) is the free-function form of list.append. Sorting and reversing live in itertools; map/filter/reduce in functools.

Tuples

Tuples are immutable lists, written with parentheses. They support all list operations except those that mutate (no append, no index assignment).

t = (1, 2, 3)
print t[0]        // 1
print len(t)      // 3
print 2 in t      // true
x, y, z = t       // destructuring
foreach (v in t) { print v }
print with commasBecause print takes a single expression, print("a", b, c) actually prints the tuple ("a", b, c), rendered as ( "a" , b , c ). To print values joined without tuple formatting, use string interpolation (print "${a} ${b} ${c}"), concatenate with &, or use format().

Dictionaries

Dictionaries map keys to values.

d = {}
d = {"name": "Rex", "age": 3}
v = d["name"]              // index access
d["age"] = 4               // set
print "name" in d          // membership on keys

Dictionary methods

dict.get(key, default) → value

Returns the value for key, or default if the key is absent (avoids a runtime error on missing keys).

dict.keys() → list

Returns a list of the dictionary's keys.

dict.remove(key) → nil

Removes the entry for key, in place.

d = {"a": 1, "b": 2}
print d.get("c", 0)    // 0
print d.keys()         // list of keys
d.remove("a")

Vectors

vec2, vec3 and vec4 are native fixed-size float vectors, unboxed directly into the value representation the same way int/float/bool are — a genuine value type, not a heap object referenced from its Value the way lists, dicts, and other native types are. Assigning, passing, or storing one always copies it; there's no way for two variables to end up sharing "the same" vector such that mutating one is observed through the other. They are used throughout the graphics API (positions, sizes, and RGBA colours as vec4).

Unlike the gfx constructors (window, batch, …), the vector constructors vec2() / vec3() / vec4() are built-in — always available, no import needed — because vectors are core value types rather than graphics objects.

v2 = vec2(1, 2)
v3 = vec3(1, 2, 3)
v4 = vec4(255, 128, 0, 255)   // often an RGBA colour

// Component access & mutation
print v3.x        // 1
v3.y = 5
v3.z += 1

// Vector addition uses ++
sum = vec3(1, 2, 3) ++ vec3(10, 10, 10)   // vec3(11, 12, 13)
ConstructorComponents
vec2(x, y).x .y
vec3(x, y, z).x .y .z
vec4(x, y, z, w).x .y .z .w

For vector length, normalisation, rotation and scaling helpers, see the math module.

Component assignment

Assigning to a component (v.x = expr) is supported on a bare variable or one level of property access (this.pos.x = expr, entity.pos.x = expr) — the common shapes real scripts use. Assigning into a vector reached through a list/dict index (list[i].x = expr) or a call's direct result (get_vector().x = expr) is a compile error rather than a silently-lost write; assign the whole vector instead (list[i] = vec3(...)). Compound assignment on a component (v.x += 1) isn't supported either — write v.x = v.x + 1.

pos = vec2(0, 0)
pos.x = 10          // pos becomes vec2(10, 0)

class Entity {
    __init__() { this.pos = vec3(0, 0, 0) }
    move(dx) { this.pos.x = this.pos.x + dx }   // one level of property access -- supported
}

Since vectors are values, not references, there's no aliasing to reason about here the way there would be for a mutable object: other = pos then later mutating pos never affects other, regardless of whether the mutation goes through a component assignment or a whole-value reassignment.

Core & type conversion

batch gfx

A batch accumulates many primitives of one type and renders them all in a single native draw call — dramatically faster than thousands of individual Lox-level draw calls. Ideal for particle systems, large scenes and real-time simulations.

type is one of the win.BATCH_* constants. Supported primitive types: cube, textured cube, sphere, triangle (3 points), and circle (flat 3D disc).

batch_instanced gfx

batch_instanced() uses GPU mesh instancing to draw very large numbers of textured cubes (100k+) in a single call. It is specialised for textured-cube instancing where hardware instancing gives the biggest win.

batch_instanced(texture, cube_size, max_instances) → batch_instanced
  • texture — the texture applied to every cube (all instances share it); commonly a render_texture's get_texture().
  • cube_size — edge length (float) of every cube.
  • max_instances — capacity (int); add() beyond this raises a runtime error.

Like batch, entries are added then drawn in one call, but the render path uses hardware instancing. Unlike batch, instances carry only a transform (position + rotation) — the texture and size are fixed at construction. The workflow is: add() every instance, call make_transforms() once to build the transform matrices, then draw(camera) each frame.

from gfx import window, camera, render_texture, batch_instanced
import random
win = window(1200, 800)
win.init()
cam = camera(vec3(0, 20, 60), vec3(0, 0, 0), vec3(0, 1, 0))

rt = render_texture(64, 64)                 // build a texture to sample
rt.clear(vec4(0, 0, 0, 255))
rt.circle_fill(32, 32, 30, vec4(255, 128, 0, 255))

cubes = batch_instanced(rt.get_texture(), 2.0, 100000)
foreach (i in range(50000)) {
    pos = vec3(random.float(-50, 50), random.float(-50, 50), random.float(-50, 50))
    cubes.add(pos, vec3(0, 1, 0), random.float(0, 360))   // position, rotation axis, angle°
}
cubes.make_transforms()                     // build matrices once, after adding

// render loop:
win.begin_3d(cam)
cubes.draw(cam)                             // all 50k cubes in one instanced call
win.end_3d()

physics_world physics

physics_world is a native 3D rigid-body simulation for spheres. Each body has a position, velocity, radius and material; step() advances them all — applying gravity, bouncing off the boundary box, and resolving body-to-body collisions — in a single native call. Fixed level geometry (floors, shelves, ramps) can be added as static boxes with add_static_box — optionally tilted, never moving — for dynamic spheres to bounce off.

Creating a world

physics_world(min_vec3, max_vec3, cell_size, gravity_vec3) → physics_world
  • min_vec3 / max_vec3 — opposite corners of the boundary box; bodies bounce off these (each body's radius is accounted for).
  • cell_size — internal collision-grid cell size; should exceed the largest body's diameter.
  • gravity_vec3 — constant acceleration applied to every body each step().

Basic usage

Register a material, add bodies to get their ids, then call step() each frame and read positions back with get_position():

from physics import physics_world
from gfx import window, camera
import random
import colour as col
world = physics_world(vec3(-10, 0, -10), vec3(10, 100, 10), 2.0, vec3(0, -0.01, 0))
mat = world.add_material(0.5, 0.3, 0.99)     // restitution, friction, damping

ids = []
foreach (i in range(20)) {
    pos = vec3(random.float(-5, 5), random.float(5, 20), random.float(-5, 5))
    ids.append(world.add(pos, vec3(0, 0, 0), 0.5, mat))
}

win = window(800, 600)
win.init()
cam = camera(vec3(0, 20, 40), vec3(0, 0, 0), vec3(0, 1, 0))
while (!win.should_close()) {
    world.step(1.0)
    win.begin()
    win.clear(vec4(30, 30, 40, 255))
    win.begin_3d(cam)
    foreach (id in ids) {
        p = world.get_position(id)
        win.sphere(p, 0.5, col.WHITE)
    }
    win.end_3d()
    win.end()
}

Worker poolThere's no shared-memory Queue the way Python's multiprocessing.Queue needs one, but spawn/send/wait_any are enough to drain a shared task queue across several workers -- the pool module below does exactly that, so most scripts don't need to hand-roll it. See PROCESS_MODULE.md for the pattern pool is built on.

socket module

import socket — raw TCP sockets, for IPC with any process (not just another Odlox instance), as a lower-level alternative to process's pickled-value pipe: send()/recv() move plain bytes as strings, with no serialisation format imposed. TCP only -- there's no Unix-domain-socket support underneath, so local IPC here means a real TCP connection over loopback ("127.0.0.1") rather than a filesystem-path socket. As with process, there's no threading model anywhere in Odlox, so accept()/recv() block by default, exactly like Process.recv() does, and try_accept()/try_recv() are the non-blocking variants a polling loop uses instead.

FunctionDescription

socket.listen(host, port, backlog=1000)Bind and start listening on host:port (host must be an IP literal, e.g. "127.0.0.1" or "0.0.0.0" -- no DNS resolution). Returns a listening Socket. Raises SocketError on failure.

c.close()
Starting a socket server as a companion processPair this with process.start() -- it launches a script (e.g. one that calls socket.listen() and serves) with no pipe attached, so the two processes talk over the socket connection instead.

pool module

import pool — fixed-size worker pools, similar to Python's multiprocessing.Pool: ProcessPool over process's spawn/send/recv/wait_any. Spawns its workers up front and keeps them alive across calls; .map() hands tasks out to whichever worker is free and returns results in task order, regardless of which worker finishes first.

Function / classDescription
pool.ProcessPool(worker_path, n_workers)Class: spawns n_workers copies of the .lox script worker_path immediately. Each worker loops "recv() a task, do work, send() a result". Workers stay alive, idle between calls, until close() kills them.
.map(tasks)Runs every item in tasks across the pool; blocks until all are done. Returns results in the same order as tasks. Safe to call more than once on the same pool -- workers are reused, not respawned, between calls.
.close()Kills and reaps every worker. Idempotent. map() raises PoolError if called afterward.
 
import pool

p = pool.ProcessPool("worker.lox", 4)
results = p.map([1, 2, 3, 4, 5])   // more tasks than workers is fine
print results                      // in task order, however workers finished
results2 = p.map([10, 20])         // same pool, same workers, reused
p.close()
LimitationIf a worker crashes mid-task, map() can't distinguish that from every worker in the pool having exited -- wait_any() doesn't tell the two apart -- so it raises PoolError either way rather than retrying or reporting which task was lost.

Key implementation notes for writing fast Lox:

  • Prefer foreach (i in range(n)) over manual counter loops — range is a native iterator.
  • Use batch / batch_instanced for large numbers of similar primitives instead of per-object draw calls.
  • Move hot per-object simulation into native types where available (e.g. physics_world) rather than per-object Lox method dispatch.
  • Short strings (40 bytes or under — identifiers, small values) are interned to a canonical pointer, so equality and method/property/global lookup are pointer compares; longer strings are ordinary garbage-collected values, not interned.

Interpreter-level optimisations include slice-indexed globals, string interning, a peephole pass with numeric superinstructions (Add_Ii/Add_Ff/Incr_Const_I/Incr_Const_F), a monomorphic inline cache on property/method access, inline call frames, and a hoisted dispatch-loop frame context.
